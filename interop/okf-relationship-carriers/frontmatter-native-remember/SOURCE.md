# remember: frontmatter-native relationship input

This directory preserves one unedited concept file from Andrew Crenshaw's public, compiler-generated [remember OKF sample bundle](https://github.com/andrewcrenshaw/remember-okf-sample-bundle/tree/3806111cad1a058585242f7ad78716c4a767c782), pinned to commit `3806111cad1a058585242f7ad78716c4a767c782`. It is a fixture export, **not** an export of remember's live corpus or a complete copy of its sample bundle. The [original file](https://github.com/andrewcrenshaw/remember-okf-sample-bundle/blob/3806111cad1a058585242f7ad78716c4a767c782/bundle/facts/okf-v0-2-conformance-fixture-lesson-e-001.md) has SHA-256 `e1b85a22821345c9d71ce0cd750f3050407badb593d3d23d4c3c5e05756623a2`, as recorded in the upstream [`SHA256SUMS`](https://github.com/andrewcrenshaw/remember-okf-sample-bundle/blob/3806111cad1a058585242f7ad78716c4a767c782/SHA256SUMS). The upstream bundle is licensed [CC0 1.0 Universal](https://github.com/andrewcrenshaw/remember-okf-sample-bundle/blob/3806111cad1a058585242f7ad78716c4a767c782/LICENSE).

The source's authoring mode is **frontmatter-native**: the exporter writes `supersedes` and `contested_by` against stable concept IDs, not paths or Markdown link occurrences. The concept file uses the bare `id: okf-conformance-fixture-001`; the upstream [manifest](https://github.com/andrewcrenshaw/remember-okf-sample-bundle/blob/3806111cad1a058585242f7ad78716c4a767c782/bundle/.manifest.json) also records its namespaced `remember://lesson/okf-conformance-fixture-001` form. Both referenced target IDs, `okf-conformance-predecessor-000` and `okf-conformance-disputer-002`, are absent from the pinned bundle. The body explicitly says there are no outbound or inbound links, so there is **no PGM link assertion to project** from this production output. A PGM version of these cases would be a separately authored adaptation, not a lossless extraction from this source.

`contested_by` is the exporter's actual spelling at this commit. Under the [proposed OKF #22 registration](https://github.com/GoogleCloudPlatform/open-knowledge-format/issues/22), it is deprecated input for `contradicts`; `contradicted_by` is a derived reverse view, never a stored input. Neither a relationship-level `verified` event nor an attributed supersession resolution appears here: `verified: []` applies to the **concept**, and the copied [bundle-root log](bundle/log.md) contains creation records only—no supersession or dismissal affirmation. The [upstream log](https://github.com/andrewcrenshaw/remember-okf-sample-bundle/blob/3806111cad1a058585242f7ad78716c4a767c782/bundle/log.md) has SHA-256 `f6940b62145d670ec331b38a590fa15c8b67be9d4d531f8d2d46b7990b84aeba` in the same pinned `SHA256SUMS`. With absent targets and no affirmation, the proposed #22 query semantics exclude no incumbent. These are proposed semantics, not an adopted OKF rule or PGM Core semantics.

Andrew [offered these cases](https://github.com/GoogleCloudPlatform/open-knowledge-format/issues/16#issuecomment-5777364164) for the interoperability exercise and [clarified that the original has no prose links](https://github.com/GoogleCloudPlatform/open-knowledge-format/issues/16#issuecomment-5778923203). That authority boundary is why this source is kept separate from the PGM-native projection fixture.
